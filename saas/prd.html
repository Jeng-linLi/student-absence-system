1. Product Overview & Goals產品概述與目標

SAAS replaces email-based absence handling with a single, policy-driven platform covering short-term leave, assessment conflict accommodation, and official-activity verification for HKUST(GZ) — designed to be portable to HKUST (Hong Kong), CUHK(SZ) and other international universities. SAAS 以政策驅動的單一平台取代電郵式請假，覆蓋短期請假、考評衝突便利安排與官方活動核實，服務香港科技大學（廣州），並可移植至香港科技大學、香港中文大學（深圳）及其他國際院校。

In scope範圍內

  • Short-term absence requests (1–30 days)短期請假（1–30 天）
  • Assessment conflict detection & accommodation考評衝突偵測與便利安排
  • Official activity rosters & auto-verification官方活動名單與自動核實
  • Approval workflow engine + SLA/escalation審批工作流與 SLA／升級
  • Notifications, dashboards, analytics, audit通知、看板、分析、審計

Out of scope (v1)範圍外（第一版）

  • Class timetabling & room booking排課與教室預訂
  • Long-term leave of absence / suspension of studies長期休學／停學
  • Grading, transcript changes成績與成績單變更
  • Staff (faculty & admin) leave management教職員請假管理
  • Disciplinary attendance enforcement出席懲戒執行

Design decision: SAAS decides accommodations, not attendance policy. Policy parameters (thresholds, SLA, routing) live in a configuration table owned by the Academic Registry, so rules change without redeploying code. 設計決定：SAAS 負責「執行學業便利安排」，不負責「制定出席政策」。門檻、SLA、路由等政策參數存放於教務處維護的配置表中，規則調整毋須重新部署程式。

5. Academic Conflict Management考評衝突管理

On submission, SAAS resolves the student's enrolments and assessment calendar for the requested date range and generates one AssessmentConflict row per clash. Instructors resolve each conflict independently. 提交申請時，SAAS 依學生的修讀紀錄與考評行事曆，在請假區間內解析出所有衝突，每個衝突產生一筆「考評衝突」紀錄；教師逐項獨立處理。

Detected conflict types偵測之衝突類型

  • Quiz小測
  • Midterm examination期中考試
  • Final assessment期末考評
  • Mandatory workshop必修工作坊
  • Laboratory session實驗課

Detection requires the assessment calendar. MVP ingests a nightly CSV/API feed from the SIS and Canvas LMS; institutions without a feed fall back to instructor-declared assessment dates. 衝突偵測依賴考評行事曆。MVP 每晚從教務系統（SIS）與 Canvas 匯入 CSV／API；若院校無匯入來源，則退回「教師自行申報考評日期」模式。

Make-up assessment安排補考New date/venue recorded; student notified記錄新日期地點並通知學生

6. Official Activity Module官方活動模組

Event Organizers and Sports Team Coordinators register activities and upload participant rosters. Students on a roster are auto-verified — no document upload, higher approval priority, and instructor notification rather than instructor approval. 活動負責人與運動隊協調員登記活動並上傳參與名單。名單內學生自動核實：毋須上傳證明、享有較高審批優先級，教師只需接收通知而無須核准。

7. Workflow Engine工作流引擎

The engine is data-driven: each request is assigned a route at submission time, computed from category, duration, and activity membership. Routes are versioned so historical requests remain reproducible. 引擎為資料驅動：每筆申請在提交時依類別、天數與活動名單歸屬計算出「路由」。路由具版本控制，歷史申請可完整重現。

Case A · Medical LeaveA 案 · 病假

Student → Instructor → Approved. Instructor may approve, reject, or request more information. If duration > 3 days, Registry countersignature is appended. 學生 → 教師 → 核准。教師可核准、駁回或要求補充資料；超過 3 天則追加教務處會簽。

Case B · Official University ActivityB 案 · 校方官方活動

Event Coordinator → Auto Verification → Instructor Notification. No approval gate; instructors receive the notice and resolve assessment conflicts only. 活動協調員 → 自動核實 → 通知教師。無審批關卡，教師僅接收通知並處理考評衝突。

Case C · Absence > 7 daysC 案 · 請假超過 7 天

Student → Program Office → Academic Registry → Instructor. Registry may impose conditions (e.g. coursework plan, minimum attendance). Instructor handles assessment accommodation. 學生 → 項目辦公室 → 教務處 → 教師。教務處可附加條件（如修課計劃、最低出席要求）；教師負責學業便利安排。

Escalation（升級機制）: if a step exceeds 50% of its SLA, a reminder is sent; at 100%, the step is escalated to the approver's delegate and the Program Office is notified. Requests still open after 150% of SLA are auto-escalated to the Academic Registry. 若某步驟用時達 SLA 五成，發送提醒；達 100% 則升級至審批人的代理人並通知項目辦公室；超過 SLA 150% 仍未處理者自動升級至教務處。

12. User Stories用戶故事

US-01 As a student, I want to submit one absence request covering all affected courses, so that I don't have to email each instructor. 作為學生，我希望提交一次申請即涵蓋所有受影響課程，毋須逐封電郵通知教師。

Acceptance: On submit, system lists affected sessions and creates one conflict record per assessment clash. 驗收：提交後系統列出受影響課節，並為每個考評衝突建立紀錄。

US-02 As a student, I want to upload a medical certificate, so that my sick leave is verified without visiting an office. 作為學生，我希望上傳醫生證明，不必親赴辦公室即可完成核實。

Acceptance: PDF/JPG/PNG ≤10 MB accepted; virus-scanned; stored encrypted in Blob with 7-year retention. 驗收：接受 ≤10MB 的 PDF／JPG／PNG；經病毒掃描；加密存放於 Blob，保存 7 年。

US-03 As a student, I want to see who is currently reviewing my request, so that I know when to expect a decision. 作為學生，我希望知道目前由誰審批，以便預期結果時間。

Acceptance: Timeline shows each step, owner, and SLA countdown. 驗收：時間軸顯示每一步驟、負責人與 SLA 倒數。

US-04 As a student on an official team roster, I want my absence auto-verified, so that I don't upload proof each time. 作為官方隊伍名單內的學生，我希望請假自動核實，毋須每次上傳證明。

Acceptance: Selecting an endorsed activity removes the document requirement; request is approved with "auto-verified" provenance. 驗收：選取已核准活動後免除文件要求；申請以「自動核實」來源核准。

US-05 As a student, I want to track granted extensions and make-up tests in one place, so that I don't miss a new deadline. 作為學生，我希望集中查看已批的延期與補考，避免錯過新期限。

Acceptance: Dashboard lists new deadlines & make-up schedule with countdown. 驗收：看板列出新期限與補考安排，附倒數提示。

US-06 As a student, I want to withdraw a request before it is decided, so that a cancelled plan doesn't count against me. 作為學生，我希望在決定前撤回申請，避免已取消的計劃仍被計算。

Acceptance: Withdraw allowed until first approval; status becomes Withdrawn; instructors notified. 驗收：首次核准前可撤回；狀態轉為「已撤回」並通知教師。

US-07 As an instructor, I want a single queue of pending requests with full context, so that I can decide in one pass. 作為教師，我希望在單一佇列中看到完整上下文的待辦，一次完成決策。

Acceptance: Queue shows student, category, dates, documents, affected assessments, student's term absence rate. 驗收：佇列顯示學生、類別、日期、文件、受影響考評與該生本學期缺席率。

US-08 As an instructor, I want to grant a make-up assessment with date and venue, so that the student knows exactly what to do. 作為教師，我希望指定補考的日期與地點，讓學生清楚知道安排。

Acceptance: Make-up option records date/venue/mode; calendar invite sent to student. 驗收：補考方案記錄日期／地點／形式，並向學生發出行事曆邀請。

US-09 As an instructor, I want to redistribute assessment weight, so that an excused student is assessed fairly without a make-up. 作為教師，我希望重新分配考評權重，使獲豁免學生毋須補考亦獲公平評核。

Acceptance: New weights sum to 100% and are recorded with effective date. 驗收：新權重總和為 100%，並記錄生效日期。

US-10 As an instructor, I want to request more information, so that I don't reject a legitimate request on incomplete evidence. 作為教師，我希望要求補充資料，避免因資料不足而駁回合理申請。

Acceptance: Request returns to student, SLA pauses, student can respond without re-submitting. 驗收：申請退回學生、SLA 暫停，學生可直接回應毋須重新提交。

US-11 As a Program Office user, I want department-wide absence statistics, so that I can spot trends early. 作為項目辦公室人員，我希望掌握全院缺席統計，及早發現趨勢。

Acceptance: Dashboard shows volume, category mix, trend chart, filterable by programme/cohort. 驗收：看板顯示申請量、類別分佈、趨勢圖，可按項目／年級篩選。

US-12 As a Program Office user, I want risk alerts, so that I can intervene before a student fails. 作為項目辦公室人員，我希望收到風險預警，在學生不及格前介入。

Acceptance: EW-1..EW-5 alerts appear in a queue with student context. 驗收：EW-1 至 EW-5 預警於佇列中顯示並附學生脈絡。

US-13 As an Academic Registry user, I want to review absences longer than 7 days, so that policy is consistently applied. 作為教務處人員，我希望覆核七天以上請假，確保政策一致執行。

Acceptance: Case C queue lists all >7-day requests with conditions field. 驗收：C 案佇列列出所有七天以上申請，附「附加條件」欄位。

US-14 As a Registry user, I want to change policy thresholds without a release, so that rules follow academic calendar changes. 作為教務處人員，我希望毋須發版即可調整政策門檻，使規則跟隨校曆變動。

Acceptance: Config UI edits thresholds/SLA/routing; changes versioned and audited. 驗收：配置介面可編輯門檻／SLA／路由；變更具版本並記錄審計。

US-15 As a Student Affairs user, I want welfare flags for repeated medical leave, so that I can offer support. 作為學生事務處人員，我希望獲悉頻繁病假的關懷標記，以便提供支援。

Acceptance: EW-3 creates a confidential case; instructors see no medical detail. 驗收：EW-3 建立保密個案；教師看不到任何醫療細節。

US-16 As a Sports Team Coordinator, I want to upload a roster once per season, so that athletes are covered for all fixtures. 作為運動隊協調員，我希望每季上傳一次名單，使運動員全季賽事均獲覆蓋。

Acceptance: CSV upload matches by student ID; unmatched rows flagged; roster snapshot timestamped. 驗收：CSV 按學號比對，無法匹配者標記，名單快照附時間戳。

US-17 As an Event Organizer, I want to register an official activity with dates, so that participants are auto-verified. 作為活動負責人，我希望登記官方活動與日期，使參與者自動核實。

Acceptance: Activity requires Program Office endorsement before rosters verify. 驗收：活動須經項目辦公室核准，名單方可生效核實。

US-18 As an Academic Advisor, I want an advisee timeline, so that I can discuss academic impact in our meetings. 作為學術導師，我希望查看導生的請假時間軸，以便在會談中討論學業影響。

Acceptance: Advisee list shows term absence rate, conflicts, accommodations. 驗收：導生清單顯示本學期缺席率、衝突與已批便利安排。

US-19 As an administrator, I want role-based access control, so that sensitive data is only visible to authorised roles. 作為系統管理員，我希望具備角色權限控制，使敏感資料僅供授權角色查看。

Acceptance: RBAC matrix enforced server-side; every read of sensitive fields audited. 驗收：RBAC 矩陣於伺服器端強制執行；敏感欄位的每次讀取均記入審計。

US-20 As an administrator, I want an immutable audit log, so that any decision can be reconstructed. 作為系統管理員，我希望有不可竄改的操作日誌，使任何決定都可還原。

Acceptance: Append-only log with actor, action, timestamp, before/after hash chain. 驗收：僅可追加的日誌，含操作者、動作、時間戳與前後雜湊鏈。

US-21 As a student, I want notifications in my preferred channel, so that I don't miss a decision because I didn't check email. 作為學生，我希望以偏好渠道接收通知，避免因未查電郵而錯過結果。

Acceptance: Channel preferences configurable per event type. 驗收：可按事件類型設定通知渠道偏好。

US-22 As an instructor, I want a Teams card with approve/reject buttons, so that I can decide without opening the app. 作為教師，我希望在 Teams 收到含核准／駁回按鈕的卡片，毋須開啟系統即可決策。

Acceptance: Adaptive Card actions call the API with the instructor's token. 驗收：自適應卡片的動作以教師憑證呼叫 API。

US-23 As a student, I want the interface in English or Chinese, so that I can work in my preferred language. 作為學生，我希望介面支援中英文，以便使用慣用語言。

Acceptance: Full zh-CN / en (and zh-HK in Phase 2) locale coverage; dates follow locale. 驗收：完整覆蓋簡中／英文（第二期增繁中）；日期格式依語系顯示。

US-24 As a student with a disability, I want the system to meet WCAG 2.1 AA, so that I can complete a request independently. 作為有障礙需要的學生，我希望系統符合 WCAG 2.1 AA，以便獨立完成申請。

Acceptance: Keyboard navigable, 4.5:1 contrast, screen-reader labels, no colour-only status. 驗收：可純鍵盤操作、對比度 4.5:1、具螢幕閱讀器標籤、狀態不單靠顏色表達。
