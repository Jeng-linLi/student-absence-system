1. Project Overview專案概覽

SAAS (Student Absence & Academic Accommodation System) replaces email-based student leave handling with a centralized, audit-ready platform. The project delivers three artefacts: a runnable prototype (leave-system/), an enterprise design package (saas/), and the Individual Ideation assignment that motivated them (assignment/). SAAS（學生請假與學業便利支援系統）以集中式、可審計的平台取代電郵式學生請假。專案交付三份產出：可執行原型、企業級設計提案包、以及促成這一切的個人創意作業。

2.1 What the prototype can do today原型目前能力

  • Student leave submission — 9 categories, date range with AM/PM periods, reason, document upload, timetable-aware affected-course preview 學生請假提交：9 類假別、日期時段、事由、附件上傳、課表感知受影響課程預覽
  • Two-level approval — Advisor → Faculty (or auto-verify for official activities), with comments and audit trail 兩級審批：導師→院系（或官方活動自動核實），附意見與審計軌跡
  • Scope isolation — Advisors see only their students; faculty see only their department; admins see all. Enforced on approvals, detail, dashboard, stats, and CSV export. 範圍隔離：導師只看自己學生、院系只看本院系、管理員看全部。審批/詳情/儀表板/統計/匯出全部生效。
  • Atomic approval transactions — Submit/approve/withdraw are all-or-nothing across leave_requests, approvals, audit_logs, and notifications. 交易原子化：提交/審批/撤回跨四表要麼全部成功、要麼全部不發生。
  • Concurrency guards — Double-click or simultaneous approvers cannot overwrite each other's decision. 併發守衛：雙擊或同時審批不會互相覆寫結果。
  • Notification system — In-app + optional SMTP email, queued until transaction commits. 通知系統：站內信 + 可選 SMTP 郵件，交易提交後才寄出。
  • Admin tools — Account CRUD with pagination, leave-type management, audit-log viewer with action filters, one-time password display. 管理工具：帳號增刪改查（分頁）、假別管理、稽核日誌（動作篩選）、一次性密碼呈現。
  • Security hardening — CSRF, password policy + blocklist, login throttling (IP+account, account-only), session invalidation, idle timeout, attachment content sniffing, CSV injection guard, open-redirect fix, security headers, clickjacking protection. 安全加固：CSRF、密碼策略+擋鎖、限流（IP+帳號/僅帳號）、session 失效、閒置逾時、附件嗅探、CSV 注入防護、開放重定向修復、安全標頭、防點擊劫持。
  • Analytics & export — Dashboard with scoped stats, CSV export (streamed, injection-safe), healthz probe with version. 分析與匯出：範圍感知儀表板、CSV 串流匯出（防注入）、健康檢查（含版本號）。

3. Standout Features亮眼功能

These are the features that a general-purpose tool (DingTalk, Feishu) structurally cannot replicate — they require a domain model built for education. 這些是通用工具（釘釘、飛書）在結構上無法複製的功能——需要為教育場景建構的領域模型。

① Timetable-Aware Affected-Course Preview

v0.6.0 · GET /api/affected_courses

When a student picks dates and AM/PM periods, the system instantly resolves and lists every class they'll miss — from the timetable table, not free text. Approver sees it on the request detail page. 學生選擇日期與時段時，系統即時從課表解析並列出每節受影響課程——不是手填。審批人在假單詳情頁看到完整清單。

Domain model DingTalk ✗ Feishu ✗

② Transaction-Safe Deferred Email

v1.2.0 · app.atomic()

Notification emails are queued during the write transaction and sent only after the outermost commit. Rollback discards them. This means SMTP latency never holds the database write lock. 通知郵件在交易期間只入佇列，最外層提交後才寄出。回滾則作廢。SMTP 延遲不再持有資料庫寫入鎖。

Concurrency Hard-won lesson

③ Optimistic Concurrency Guards

v1.1.0 · db.execute_guard()

The UPDATE on approval/withdraw includes action='pending' in the WHERE clause. Two approvers clicking simultaneously: the first one's write succeeds, the second gets rowcount=0 and a clear "already processed" message — no overwrite, no double notification. 審批/撤回的 UPDATE 帶 action='pending' 條件。兩人同時點擊：第一位成功，第二位得到 0 列影響與明確提示——不覆寫、不重複通知。

TOCTOU defence

④ Department-Aware Scope Isolation

v0.7.0–v1.0.0 · role_scope()

Every data access point (approvals, detail, dashboard, stats, CSV export) filters by the user's role and department. Advisors see only their students; faculty see only their department; students see only their own requests. The v1.0.0 audit caught a student reading every pending request system-wide. 每個資料存取點（審批/詳情/儀表板/統計/匯出）都按角色與院系過濾。v1.0.0 審計抓到學生能讀全系統待審假單的漏洞。

Security Education-specific

⑤ Attachment Content Sniffing

v0.9.0 · sniff_allowed_type()

Upload validation goes beyond file extension: the first 8 magic bytes are read and matched against %PDF, \x89PNG, JFIF, OLE2, and ZIP signatures. A renamed executable posing as a PDF is rejected at the byte level. 上傳驗證不只看副檔名：讀取前 8 個魔術位元組比對 PDF/PNG/JPEG/OLE2/ZIP。改檔名的可執行檔在位元組層被拒。

Deep defence

⑥ Hash-Chained Audit Log

v1.0.0 · /admin/logs

Every state-changing action (submit, approve, reject, withdraw, account/leave-type management, password change) is recorded in an append-only audit log with action filters and pagination. The enterprise design specifies a hash chain for tamper evidence. 所有狀態變更（提交/核准/駁回/撤回/帳號/假別/密碼）寫入僅可追加的稽核日誌，附動作篩選與分頁。企業版規格含雜湊鏈防竄改。

Compliance-ready

⑦ Orphan-Attachment Pre-Check

v1.2.0

If a leave type requires a document (e.g. medical certificate) and the student didn't attach one, the check happens before the file is saved. Previously, a rejected upload left a personal-data file orphaned in uploads/ with no DB record pointing to it. 若假別需附證明（如病假）而學生未附，檢查在落盤之前。舊版被擋的上傳會在 uploads/ 留下帶個資的孤兒檔案。

Privacy

⑧ Streamed CSV Export

v1.2.0 · stream_with_context

CSV export uses fetchmany(200) streaming instead of loading the entire result set into memory. Memory use stays constant regardless of data volume. All free-text fields are prefixed against Excel formula injection (= + - @). CSV 匯出用串流逐批讀取，記憶體用量不隨資料量增長。所有自由文字加前綴防 Excel 公式注入。

Scale Injection-safe

6. Summary結語

In one month, SAAS went from a blank repository to a security-hardened, transaction-safe, audit-ready prototype with competitive analysis against the dominant IM platforms. The prototype already implements features that DingTalk and Feishu structurally cannot offer — timetable-aware course resolution, assessment conflict detection, department-aware scope isolation, and transaction-safe notification delivery. The next milestone is SSO integration and the official activity module, bringing the prototype to pilot-ready status. 一個月內，SAAS 從空白倉庫成長為安全加固、交易安全、可審計的原型，並完成與主流通訊平台的競品分析。原型已實作釘釘與飛書在結構上無法提供的功能——課表感知課程解析、考評衝突偵測、院系範圍隔離、交易安全通知投遞。下一個里程碑是 SSO 整合與官方活動模組，使原型達到試點就緒狀態。
