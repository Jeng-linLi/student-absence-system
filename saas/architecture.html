System Architecture & API Design 系統架構與 API 設計

Cloud-native on Azure: Next.js front end, NestJS microservices, PostgreSQL, Redis, Blob Storage, Microsoft Entra ID SSO. 雲原生架構，部署於 Azure：Next.js 前端、NestJS 微服務、PostgreSQL、Redis、Blob 儲存，並以 Microsoft Entra ID 單一登入。

3. Authentication Flow (Microsoft Entra ID / OIDC)認證流程（Entra ID / OIDC）

    │◄─────────────────┤   HttpOnly, Secure, SameSite=Strict           │
    │ 9. Subsequent API calls: Authorization: Bearer <JWT>            │
    │                  ├─ gateway verifies signature + role claims ────►│
  • PKCE + OIDC; MFA and Conditional Access enforced by Entra ID, not by SAAS. 採用 PKCE + OIDC；多重要素驗證與條件式存取由 Entra ID 負責，不由 SAAS 自行實作。
  • Roles derived from Entra ID security groups + local DB overrides (e.g. delegated approver). 角色由 Entra ID 安全性群組 ＋ 資料庫本地覆寫（如代理審批人）共同決定。
  • Short-lived access tokens (15 min) with rotating refresh tokens; refresh reuse detection revokes the family. 存取憑證僅 15 分鐘，刷新憑證輪替；偵測到重用即撤銷整個憑證族。
  • Break-glass local admin account: hardware-key only, no password, quarterly drill. 緊急本地管理帳號：僅允許硬體金鑰、無密碼、每季演練。

4. RBAC Permission ModelRBAC 權限模型

Permissions are enforced server-side at the gateway and at the service layer; the UI only hides what the user cannot do. Scope qualifiers: own · course · programme · department · all. 權限於閘道與服務層的伺服器端強制執行；介面僅隱藏使用者無權執行的動作。範圍限定詞：own（本人）· course（所授課程）· programme（所屬項目）· department（所屬院系）· all（全校）。

5. REST API DesignREST API 設計

Conventions: /api/v1/…, JSON, camelCase, cursor pagination (?cursor=&limit=), Idempotency-Key on all writes, RFC 7807 problem+json errors, ETag on reads. 慣例：/api/v1/…、JSON、駝峰命名、游標分頁（?cursor=&limit=）、所有寫入附 Idempotency-Key、錯誤採 RFC 7807 problem+json、讀取附 ETag。

Data residency: production deployed to Azure China East 2 (Shanghai) for mainland operation, or Azure East Asia (Hong Kong) for HKUST main campus — decided by the data classification review. 資料存放地：生產環境部署於 Azure 中國東部 2（上海）以支援內地運作，或 Azure 東亞（香港）以支援清水灣校園——由資料分級評審決定。

Environments（環境）: dev → staging → UAT (pilot cohort) → prod. Database migrations are forward-only and applied via CI; destructive changes require a two-release deprecation window. 環境鏈：開發 → 測試 → UAT（試點群體）→ 生產。資料庫遷移僅允許向前，並由 CI 執行；破壞性變更須經兩個版本的棄用期。
