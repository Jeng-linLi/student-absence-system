學生線上提交假單 → 導師審批 → （必要時）院系複核 → 核准生效。Flask + SQLite，開箱即跑。

## 審批規則

- 請假 **≤ 3 天**：導師核准即生效。
- 請假 **> 3 天**，或假別標記「需院系審批」（公假、喪假）：導師核准後自動轉院系複核。
- 病假**必須**上傳證明文件。
- 駁回必須填寫理由，理由會通知學生。
- 天數按半天粒度計：同日 AM→PM = 1 天，同日 AM→AM = 0.5 天。
- **批次審批（v1.6.0）**：待審清單可勾選多張一次核准／駁回，整批包在單一交易內
  （要嘛全成、要嘛全退）；每張都重新驗權，越權、已結案或已被他人處理的單只被略過，
  單次上限 50 張。

## 表單校驗

- 單張假單最多 **90 天**。
- 最多可回溯補請 **30 天**內的假。
- **同一區間不可重複請假**；被阻擋時會提示衝突的假單編號。已駁回／已撤回的假單不佔用區間。
- 同一天請假時，**結束時段不可早於開始時段**（同日「下午→上午」是矛盾輸入：天數算 0.5、受影響課程卻按全天計）。
- 自由文字長度上限：事由 **500 字**、審批意見 **300 字**、聯絡電話 **30 字**（前端 `maxlength` 先擋，後端再校驗）。
- 聯絡電話格式：僅能包含數字與 `+ ( ) -` 空格（非必填；填了就必須像支電話）。
- 附件上限 **8 MB**，超出時頁面提示「上傳內容過大」並導回（不會出現白底錯誤頁）。

## 課表 × 請假（受影響課程）

- 學生在「提交假單」頁選定**起訖日期**與**上午／下午時段**後，系統即時算出並顯示請假期間會錯過的課程（日期、星期、時段、課程代碼）。
- 按半天粒度：同日 AM→PM 為全天；單一時段只列該上午／下午的課；多日假的中間日為全天。
- 假單送出時，受影響課程一併寫入 `leave_requests.affected_courses`（JSON），假單詳情頁可見，方便導師判斷課程衝突。
- 資料來源為 `timetable` 表，**逐生存放**；`seed` 寫入的那份一律標 `source='demo'`，
  頁面會明白標示「這是示範資料」。正式環境請匯入真實課表或對接 SIS / LMS。

## 課表檔（v1.7.0 · 逐生課表）

一列一節課，CSV。`#` 開頭為註解，表頭可省略（省略時按下列順序解讀）：

```
# 學號,星期,開始時間,結束時間,課程代碼,類型,教室,備註
2024001,mon,09:00,10:20,AIAA 2205-L01,Lecture,"Rm 102, A棟",W4
2024002,mon,13:00,14:20,DSAA 2010-L02,Lab,Rm 205
```

- **欄名很寬鬆**：中英文、簡繁與常見別名都收（`student_no`／`學號`／`学号`、`weekday`／`星期`、
  `start_time`／`開始時間`、`course`／`課程代碼`…），教務處匯出的檔可以直接貼。
- **星期**：`mon`…`fri`、英文全名、`週一`／`周一`／`星期一`、`1`…`5`。週末列會被擋下並列為錯誤。
- **時間**：`9:00` 與 `09:00` 都收，一律以**零填充的 `HH:MM`** 存庫（`'9:00' < '12:00'` 是
  `False`，不補零會把上午的課判成下午的課）。
- **模式**：`replace`（預設）對「檔案中出現的學生」先清空再寫入，對應教務處整份匯出；
  `merge` 只新增／更新，適合增量補課。同一份檔重複匯入不會長出重複的課（冪等）。
- **查無學號、格式錯誤的列不中斷匯入**：錯列會連同行號回報，其餘照常寫入。
- 單次上限 5,000 節課。

三種進場方式：

| 方式 | 說明 |
|---|---|
| 管理後台 | `/admin/timetable`：覆蓋率警示 → 選學生 → 週課表 → 單筆增刪，或貼上／上傳 CSV |
| CLI | `flask import-timetable data/timetable-sample.csv`（加 `--merge` 走增量模式） |
| 檢視 | `/timetable`：學生看自己的；導師／院系／管理員可選學生查看 |

> 覆蓋率（`timetable_coverage()`）是管理頁第一眼的數字：**多少人的課表還是示範資料**。
> 不把它降下來，整套「課表感知」都只是裝飾。

## 校曆檔（學期／假日／補課日）

系統吃一份純文字校曆檔，三種行（`#` 開頭為註解）：

```
term    2026-09-01  2026-12-25  2026-27 秋季學期
holiday 2026-10-01  2026-10-07  國慶節
makeup  2026-10-10  fri         補星期五課程（國慶假期調課）
```

- `term`：學期起訖日＋標籤；`apply_calendar()` 會把涵蓋今天的學期自動設為目前（已有目前學期則不擅改）。
- `holiday`：放假區間，**含端點自動展開成每一天**；單日只需寫一個日期、第二欄留空。假日不列受影響課程。
- `makeup`：補課／調課日，第三欄是「被補的星期幾」——可用 `mon`…`fri`、英文全名、`週五`／`周五`／`星期五`、`1`…`5`，或直接給一個日期（取那天星期幾）。補課日即使落在週六／假日也照常上課，且改按被補那天的課表計缺課。
- 單行格式錯誤不會中止匯入：錯行會列在回應的 `errors`，其餘正確照常寫入。重複匯入採冪等 UPSERT，不會長出重複資料。

三種進場方式：

| 方式 | 說明 |
|---|---|
| 管理後台 | `/admin/terms` 的「校曆檔匯入」卡片：一鍵帶入內建預設，或貼上文字 |
| CLI | `flask import-calendar [path]`；不帶路徑時自動挑選涵蓋今天的內建校曆 |
| 首次啟動 | `terms` 表為空且內建檔涵蓋今天時，`seed_calendar()` 直接匯入真實校曆，否則回退佔位學期 |

內建檔放在 `data/`，目前收錄 `hkustgz-2026-27.txt`（港科大（廣州）2026–27 學年，四學期制）。檔頭記錄來源 URL 與原文「2027 假期為 TBC」警告——政府約 2026-11 公告後，改檔重跑 `flask import-calendar` 即可更新。`PRESETS` 白名單擋路徑穿越，只認登錄過的檔名。

## 備份、驗證與還原（v1.14.0）

備份包是一個目錄，內含一致性的 `database.sqlite3` 快照、可選的 `uploads/`，以及記錄
格式版本、應用版本、UTC 建立時間、每個檔案大小與 SHA-256 的 `manifest.json`。
資料庫使用 SQLite 在線備份 API，不是直接複製仍在寫入的資料庫檔。

```bash
# 建立完整備份；預設輸出至 backups/leave-backup-<UTC>-<id>/
flask backup

# 只備份資料庫；也可改用 --output-dir DIR 指定備份父目錄
flask backup --no-uploads

# 還原前必做：驗證清單、SHA-256、SQLite 完整性與核心資料表（不修改資料）
flask verify-backup backups/leave-backup-20261105T120000Z-abcd1234

# 先停止所有應用進程，再明確確認還原
flask restore-backup backups/leave-backup-20261105T120000Z-abcd1234 --yes

# 只還原資料庫，完整備份中的附件與目前 uploads/ 都不動
flask restore-backup backups/leave-backup-20261105T120000Z-abcd1234 --yes --db-only
```

- **還原前必須停止應用**：先跑 `verify-backup`，確認備份來源與時點正確，再加 `--yes`。
  還原只提供 CLI，沒有 Web 入口；未加 `--yes` 會在修改任何資料前拒絕執行。
- **可回退**：每次還原會把原資料庫、`-wal`／`-shm` sidecar 與將被替換的附件保存到
  `restore-rollbacks/pre-restore-*`。安裝後會再次檢查資料庫，失敗時嘗試補償原狀；
  無論成功或失敗都應保留該目錄，確認系統正常後再依留存政策處理。
- **附件語意**：資料庫專用備份本來就沒有附件；還原這種備份，或對完整備份加
  `--db-only`，都不會清空或替換目前的 `uploads/`。
- **遞迴防護**：完整備份拒絕把輸出目錄設在附件目錄內，避免暫存備份再次被納入複製。
- **安全驗證**：拒絕絕對路徑、`..` 路徑穿越、反斜線、重複或未列出檔案與符號連結；
  即使攻擊者重算 manifest 雜湊，非 SQLite 或缺少核心資料表的快照仍會被拒絕。
- **個資與密鑰邊界**：備份包及 pre-restore 副本含有學生資料與病假證明等個資，預設目錄
  已納入 `.gitignore`，不得提交 Git 或放進公開儲存；應限制檔案權限、加密異機副本並訂留存期。
  環境變數、SMTP 密碼、Flask secret、SSO client secret 與部署組態**不在備份包內**，
  災難復原時須由部署秘密管理流程另行恢復。
- **定期演練**：至少在隔離環境定期執行「備份 → 驗證 → 還原 → 登入抽查假單與附件」，
  並記錄恢復時間與結果；只確認備份目錄存在，不代表真的可復原。正式部署仍應安排異機
  備份、加密、留存輪替與監控告警。

## 未來智能化（v1.15.0–v1.16.0 規劃，非本版功能）

這兩版新增的是**路線、治理與倫理邊界**，不是模型功能。完整藍圖見
[`../AI-ROADMAP.md`](../AI-ROADMAP.md)，倫理框架與上線檢核表見
[`../AI-ETHICS.md`](../AI-ETHICS.md)，企業提案的交付閘門見
[`../saas/plan.html`](../saas/plan.html) §5.1／§5.2。

- **現況**：所有審批、額度、受影響課程、權限與稽核仍由確定性規則處理；沒有 AI／LLM 呼叫、
  沒有新套件、沒有個資外送。
- **順序**：H0 政策版本／去識別化／評估／特徵開關（**與倫理審查並行**）→ H1 規則式智慧 →
  H2 影子模式與受限建議 → H3 唯讀副本上的匯總洞察。
- **紅線**：AI 只能輔助，不得決定結果、不得放寬 `role_scope()`、不得自由生成政策、
  不得把原始事由或證明附件送外部模型；學生可無痕、免理由要求全程人工處理。
- **倫理**：合規不等於倫理。學生可查閱／更正／刪除建議且不影響正式假單；
  不得以建議採納率考核審批人；含學生代表的獨立倫理審查對每次升級有否決權；
  事故後須**復權**回原狀，舉證責任在學校。同意不是禁止用途的萬用授權。
- **回退**：特徵開關、逾時降級、熔斷與還原演練都通過前，不讓模型進生產路徑；
  發生自動決策、個資外流、無法解釋的建議，或學生拒絕 AI 被記錄／差別對待，即退回純規則流程。
- **維運勾稽**：未來若真的新增 `ai_suggestions` 等表，必須同步納入 `backup.py` 的備份、
  manifest 驗證與還原演練，否則「可刪除建議」與「可還原」會互相矛盾。

## Email 通知偏好與每日摘要（v1.19.0）

通知中心提供三種本人偏好：**即時 Email**、**每日摘要（合併為一封）**、**關閉一般通知 Email**。
沒有偏好記錄的既有帳號維持舊版即時 Email 行為。無論選哪種模式，**站內通知都會保留**；
密碼重設、Email 驗證等安全郵件不受一般通知退訂影響。

選擇每日摘要後，一般通知會以 `digest_pending=1` 持久化，不立即寄信。部署環境須每日由 cron
或工作排程器執行：

```bash
flask send-digests                 # 寄送所有到期待送摘要
flask send-digests --claim-ttl 30  # 回收超過 30 分鐘的異常中斷認領
```

worker 按使用者認領待送通知，在資料庫交易外合併寄信；失敗會保留待送並釋放認領，供下一輪
重試。SMTP 未配置時不會清除待送狀態。部分失敗時 CLI 回傳失敗狀態，便於排程監控。
切換為即時或關閉會取消尚未寄出的摘要，worker 也會複核目前偏好；已進入 SMTP 投遞的郵件
無法撤回，站內通知與寄送歷史不受影響。
**投遞語意為 at-least-once**：若 SMTP 已收信、但程序在資料庫標記完成前被強制終止，極端情況
仍可能重複寄送；正式環境應配置失敗告警與送達監控，不應宣稱 exactly-once。

## 安全設計

| 項目 | 做法 |
|---|---|
| CSRF | 所有 POST 表單需帶 session 內的 CSRF token，不符者直接拒絕 |
| 安全標頭 | 回應加 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy` 與基本 `Content-Security-Policy`（含 `frame-ancestors 'none'）；動態頁面另加 `Cache-Control: no-store`（登出後「後退」不復現資料） |
| Session | 登入成功時重設 session（防 fixation）；cookie 設 `HttpOnly` + `SameSite=Lax`；閒置超過 `LEAVE_SESSION_IDLE_MINUTES`（預設 480 分鐘）需重新登入 |
| Session 作廢 | 管理員重設密碼或使用者自改密碼後，`users.pwd_changed_at` 更新，登入早於此時間的舊 session 一律登出（簽名 cookie 無法逐出，以時間戳記檢驗） |
| 登入限流 | 兩把鎖：`IP+帳號` 與 `僅帳號`（換 IP 也躲不掉），5 分鐘內失敗 8 次即鎖定；計數寫入 `login_attempts` 表——重啟不清零、多進程一致（正式環境量大可換 Redis，介面已隔離） |
| 附件存取 | 僅本人、該生導師、同院系審批人、管理員可下載；檔名含隨機字串防枚舉 |
| 附件內容 | 副檔名白名單之外，另依檔案頭魔術位元組（`%PDF`／PNG／JFIF／OLE2／ZIP）驗證真實格式——副檔名可以改，檔案頭改不了 |
| 密碼 | 長度 8–128 碼、須含大寫／小寫字母與數字、不可與帳號相同、不可與舊密碼相同、不可為常見弱密碼（`COMMON_PASSWORDS` 擋鎖，比對忽略大小寫）；管理端設定的密碼只在回應中呈現一次，不寫進 session cookie |
| SQL | 全部參數化查詢 |
| CSV 匯出 | 自由文字若以 `= + - @` 開頭會加 `'` 前綴，防止 Excel／Sheets 公式注入 |
| 帳號枚舉 | 帳號不存在時也跑一次固定 dummy hash 比對，拉平與「密碼錯誤」的回應時間差 |
| 自助密碼重設 | `/forgot` 對已登記與未登記的 Email 一律回同一句泛用訊息（不洩漏帳號是否存在）；重設信含一次性時效連結（`LEAVE_RESET_TOKEN_MINUTES` 預設 30 分鐘），DB 只存 token 的 SHA-256 雜湊；兌換守衛 `used_at IS NULL` 與寫入新密碼同交易（併發雙開只有一方成功，守衛影響 0 列的後到請求會看到連結失效而非重設成功，v1.19.2）；同一帳號一小時內申請上限 `LEAVE_RESET_MAX_PER_HOUR`（預設 5，防郵件轟炸）；重設成功即視為 Email 已驗證並刷新 `pwd_changed_at` 使所有舊 session 立即失效（v1.12.0，對應 GAP-ANALYSIS B1） |
| Email 驗證 | `users.email_verified` 欄位（預設 0，舊庫自動遷移）；管理端新增含 Email 的帳號且 SMTP 已配置時自動寄驗證信，`/verify/<token>` 一次性連結兌換後轉 1 並留稽核——確保重設信不會發進死信箱（v1.12.0，對應 GAP-ANALYSIS B2）。管理員真正修改或清空 Email 時，會重設驗證狀態並作廢全部未使用的驗證／重設 token；新地址非空且 SMTP 已配置時，於交易提交後寄出新驗證信。僅調整大小寫或首尾空白不觸發重設（v1.20.0） |
| 郵件絕對連結 | 重設密碼與 Email 驗證連結只使用固定、經校驗的 `LEAVE_BASE_URL`，不從請求 `Host` 生成，避免 Host header poisoning 將一次性令牌導向攻擊者網域（v1.19.1） |
| 個資讀取稽核 | 三條跨範圍 PII 讀取路徑——統計頁（`/stats`）、CSV 匯出（`/export`）、帳號清單（`/admin/users`）——每次存取皆寫入 `view_pii`／`export` 稽核軌跡，誰看過／匯出過全範圍個資皆可追溯（v1.9.0，對應 GAP-ANALYSIS D3） |
| 單張詳情頁 PII 稽核 | `/request/<rid>` 會露出事由、聯絡電話、附件與各級審批意見；非當事人（導師／院系／管理員）每次檢視寫一筆帶 `request_id` 的 `view_pii`，學生看自己的單不記；稽核明細只記「誰、何時、看了哪一張」，**不抄學號／事由／電話**（v1.18.0，關閉 GAP-ANALYSIS D3 細粒度稽核） |
| 輸入與匯入邊界 | `MAX_AFFECTED_DAYS = 360` 擋掉課表預覽 API 的超大日期區間（原本單一 GET 可跑 3.6 萬次逐日迴圈）並白名單檢查時段；校曆檔與假日批次匯入整批包進 `atomic()`，失敗不再留下半批資料卻回報「資料庫未變更」；額度設定以 `math.isfinite()` 拒收 NaN／±Inf（原本會讓限額永久靜默失效）；Email 驗證改用 `execute_guard()` 的影響列數判定一次性 token，失敗不改 `users`、不留稽核（v1.18.0） |
| 附件留存期與銷毀 | 終態假單（approved／rejected／withdrawn）的證明附件超過 `LEAVE_ATTACHMENT_RETENTION_DAYS`（內建 365）後，由 `purge_expired_attachments()` 先備份至 `attachments_purged/` 再銷毀、清空 `attachment` 欄並寫一筆 `purge_attachment` 稽核（可由 `/admin/cron/purge-attachments` 或 `flask purge-attachments` 觸發，支援 `dry_run`），落實 PIPL 留存最小化（v1.10.0，對應 GAP-ANALYSIS D1）。同一檔案被多張假單引用時按檔名分組：仍有未到期引用就只解除到期假單的引用並保留實體檔；全部引用到期才移動一次，資料庫失敗會回滾並恢復檔案（v1.20.0） |
| 附件掃毒 | 上傳證明文件先落系統臨時檔過掃毒引擎（`scan_file_for_malware()`，相容 ClamAV 退出碼：0=乾淨／1=感染），乾淨才移入 `uploads/`——感染檔自始不進附件區、不寫假單、寫 `av_block` 稽核。組態門控：設 `LEAVE_AV_CMD`（如 `clamdscan --no-summary {file}`）即啟用，未配置則通道關閉照常運行；掃描器故障依 `LEAVE_AV_FAIL_POLICY`（預設 `reject` fail-closed）處理，逾時 `LEAVE_AV_TIMEOUT`（30 秒）。存量重掃 `flask av-scan`：感染檔隔離到 `uploads/quarantine/`、清空全部引用假單的欄位並逐張留稽核；資料庫更新失敗時會嘗試恢復原檔並以非零狀態中止，避免留下指向已隔離檔案的引用（v1.11.0，對應 GAP-ANALYSIS D2；共享引用與失敗補償於 v1.20.0 補強） |
| 備份與還原 | SQLite 在線快照＋可選附件；manifest 記錄大小與 SHA-256，並檢查 SQLite 完整性、核心資料表、檔案清單、路徑與符號連結。還原只走 CLI、須停止應用並加 `--yes`；保留 pre-restore 副本，失敗嘗試補償原狀。DB-only 不動現有附件（v1.14.0，對應 GAP-ANALYSIS E3） |
| 後台防呆 | 管理員不可停用自己、不可停用最後一位在職管理員；新增帳號強制角色白名單、帳號格式、Email 格式與導師歸屬校驗 |
| 角色下限 | 「待我審批／全部假單」僅審批人與管理員可進入（v1.0.0 前學生可翻全系統待審假單）；儀表板彙總數字同樣依角色收斂範圍 |
| 列表搜尋 | `/my`、`/approvals`、`/stats`、`/export` 共用 `q`／`date_from`／`date_to`：關鍵字一律參數化並以 `ESCAPE '!'` 跳脫 `%`／`_`／`!`（輸入 `%` 不會變成全表匯出），可搜欄名由程式碼寫死；日期採「請假區間與查詢區間有交集」語意；搜尋條件只 `AND` 上 `role_scope()`／`todo_scope()`，只收窄不放寬（v1.13.0，對應 GAP-ANALYSIS E4） |
| 上傳邊界 | 附件超過 8 MB 回 413 並友善導回；超長原始檔名先截斷再落盤（避免超過檔案系統檔名上限而 500） |
| 開放重定向 | 400／413 的導回目標只沿用 Host 與本站相同的 referrer，其餘一律回 dashboard（referrer 是攻擊者可控的完整 URL） |
| 寫入原子性 | 提交／審批／撤回的多表寫入包在交易裡：要麼全部生效、要麼全部不發生；審批與撤回另以 `action='pending'`／`status='pending'` 條件守衛，雙擊或併發點擊只會生效一次，第二位操作者收到明確提示 |
| 通知可靠性 | Email 通道連線帶逾時（預設 10 秒，`LEAVE_SMTP_TIMEOUT` 可調）——郵件伺服器不可達時請求不會無限期掛起；且郵件不在交易內同步寄出：交易期間只入佇列，最外層交易提交後才寄（回滾則作廢），SMTP 連線期間不會佔著 SQLite 寫入鎖；撤回院系級假單時院系審批人同樣收到通知 |
| 院系完整性 | 學生與院系帳號必須填寫院系（新增與編輯兩路校驗）——審批範圍依院系匹配，空院系的學生會掉進「沒人審得了」的死角 |

> `SECRET_KEY` 預設為開發用值，部署前請設環境變數 `LEAVE_SECRET`；
> 走 HTTPS 時再加 `LEAVE_COOKIE_SECURE=1`。

## 功能清單

| 角色 | 功能 |
|---|---|
| 學生 | 提交假單（含附件、**依課表預覽受影響課程**；受本學期額度限制，超額被擋）、我的假單（狀態篩選＋關鍵字／日期區間搜尋＋分頁）、**我的課表**、撤回、查看審批進度與操作日誌、儀表板額度用量板、修改密碼 |
| 導師 | 待我審批（分頁＋搜尋）、全部假單（分頁＋狀態篩選＋搜尋）、核准/駁回、**批次審批**、**查看轄下學生課表**、班級請假統計（可搜尋與限定日期區間）、CSV 匯出（串流，記憶體不隨資料量成長，可帶列表篩選）、修改密碼 |
| 代理人 | 被委託期間與原審批人同一視角：看得到、審得動、附件打得開、通知同步收（過期自動失效） |
| 院系 | 同導師（第 2 級複核，範圍為所屬院系）；亦受院系層級委託；**可查本院系學生課表** |
| 管理員 | 帳號管理（分頁＋角色篩選）、停用/編輯、重設密碼、假別管理（是否需證明、是否需院系）、稽核日誌（動作篩選＋分頁）、委託審批管理（新增/刪除）、改派導師、學期管理（目前學期互斥）、每學期每假別額度設定、校曆假日（單日新增＋批次匯入）、**校曆檔匯入（學期／假日區間／補課日，內建預設一鍵帶入）**、**補課日管理（移除）**、**課表管理（覆蓋率警示／逐生週課表／單筆增刪／CSV 匯入）**、手動觸發催辦 |
共通：站內通知（分頁＋未讀篩選＋單則標為已讀；可選 Email 通道，需設定 `LEAVE_SMTP_*`）、操作日誌（誰在何時做了什麼）、PII 讀取稽核（統計頁／CSV 匯出／帳號清單每次存取皆留 view_pii／export 軌跡）、附件留存期與銷毀（終態假單逾保存期即先備份再銷毀並留 purge_attachment 稽核）、附件掃毒（上傳先掃後落盤、感染拒收並留 av_block 稽核）、淺色/深色主題切換。
維運：`GET /healthz` 健康檢查（無需登入，回傳 JSON，資料庫異常時回 503）；`/admin/cron/escalate` 催辦升級（可設 `LEAVE_CRON_TOKEN` 給外部 cron，`LEAVE_ESCALATE_DAYS` 調門檻，同一單 24 小時只催一次）；`/admin/cron/purge-attachments` 附件留存期銷毀（同 escalate 之 token 鑑權，`LEAVE_ATTACHMENT_RETENTION_DAYS` 調留存期，支援 `dry_run`）、`flask purge-attachments [--days N] [--dry-run]` 手動觸發同一邏輯；`flask av-scan [--no-quarantine]` 存量附件重掃（感染檔隔離到 `uploads/quarantine/`，供病毒庫更新後補掃）；`flask import-calendar [path]` 匯入／更新校曆、`flask import-timetable <csv> [--merge]` 匯入／更新課表（皆為冪等，政府公告假期或課表異動後重跑即可）；`flask backup [--no-uploads]`、`flask verify-backup <bundle>`、`flask restore-backup <bundle> --yes [--db-only]` 提供可驗證、可回退的備份還原（詳見「備份、驗證與還原」）。

| `SSO_ROLE_CLAIM` | （空） | 群組／角色聲明；有值且開啟自動開通時用來決定新帳號角色 |
| `SSO_DEFAULT_ROLE` | `student` | 自動開通時的預設角色（claim 角色不在白名單內時回落到此） |
| `SSO_PROVISION` | `0` | 設 `1` 時對「對應不到的 IdP 使用者」自動開通新帳號（密碼為隨機強雜湊，只能走 SSO） |
| `SSO_AUTO_LINK_EMAIL` | `1` | 設 `1` 時用 email 自動連結既有本地帳號；設 `0` 關閉此行為 |

## 單一登入（SSO / OIDC，v1.8.0）

標準 OIDC 授權碼流程已接好，但**預設關閉**——四個必要 `SSO_*` 端點／參數（`SSO_CLIENT_ID`、
`SSO_AUTHORIZE_URL`、`SSO_TOKEN_URL`、`SSO_USERINFO_URL`）齊全才啟用。啟用後：

- 登入頁出現「使用學校帳號登入」按鈕，點擊跳轉 `/login/sso` → IdP；
- IdP 回呼 `/callback`：先校驗 `state`（防 CSRF／授權碼注入），再兌換 code → 取 userinfo →
  對映到本地使用者 → 建立 session。任一環節失敗一律退回本地登入並閃錯，**不暴露錯誤細節**。
- 身分對映優先序（`sso.resolve_user`）：① `external_id` → ② username claim →
  ③ email 自動連結（可關） → ④ 自動開通（僅 `SSO_PROVISION=1`，新帳號給隨機強雜湊，
  **只能走 SSO**）。
- **本地帳密登入永遠保留為災難備援**：SSO 掛掉時管理員仍能以帳密進系統。

> ⚠️ 本版交付的是**接線通道**，不是「已完成 SSO 對接」：真實 IdP 連線參數與
> 群組／角色聲明 → 本地角色的對映規則屬各校部署設定，本倉不內含任何一家學校的憑證或假設。
> 生產環境還應補：ID-token 簽章驗證、nonce 重放防護。
