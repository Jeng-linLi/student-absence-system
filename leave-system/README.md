# 線上請假系統（原型 v1.3.0）

學生線上提交假單 → 導師審批 → （必要時）院系複核 → 核准生效。Flask + SQLite，開箱即跑。

## 啟動

```bash
# 或雙擊 start.bat
"C:\\Users\\Johnny\\.workbuddy-ai\\binaries\\python\\envs\\default\\Scripts\\python.exe" app.py
```

打開 <http://127.0.0.1:5055>。首次啟動自動建庫並寫入示範資料。

## 審批規則

- 請假 **≤ 3 天**：導師核准即生效。
- 請假 **> 3 天**，或假別標記「需院系審批」（公假、喪假）：導師核准後自動轉院系複核。
- 病假**必須**上傳證明文件。
- 駁回必須填寫理由，理由會通知學生。
- 天數按半天粒度計：同日 AM→PM = 1 天，同日 AM→AM = 0.5 天。

## 表單校驗

- 單張假單最多 **90 天**。
- 最多可回溯補請 **30 天**內的假。
- **同一區間不可重複請假**；被阻擋時會提示衝突的假單編號。已駁回／已撤回的假單不佔用區間。
- 同一天請假時，**結束時段不可早於開始時段**（同日「下午→上午」是矛盾輸入：天數算 0.5、受影響課程卻按全天計）。
- 自由文字長度上限：事由 **500 字**、審批意見 **300 字**、聯絡電話 **30 字**（前端 `maxlength` 先擋，後端再校驗）。
- 聯絡電話格式：僅能包含數字與 `+ ( ) -` 空格（非必填；填了就必須像支電話）。
- 附件上限 **8 MB**，超出時頁面提示「上傳內容過大」並導回（不會出現白底錯誤頁）。

## 課表 × 請假（受影響課程）

- 學生在「提交假單」頁選定**起訖日期**與**上午／下午時段**後，系統即時算出並顯示請假期間會錯過的課程（日期、星期、時段、課程代碼）。
- 按半天粒度：同日 AM→PM 為全天；單一時段只列該上午／下午的課；多日假的中間日為全天。
- 假單送出時，受影響課程一併寫入 `leave_requests.affected_courses`（JSON），假單詳情頁可見，方便導師判斷課程衝突。
- 資料來源為 `timetable` 表；`seed` 會寫入一份**示範課表**（demo 學生共用，週一至週五）。正式環境請改由 SIS / LMS 同步，勿依賴硬編碼。

## 安全設計

| 項目 | 做法 |
|---|---|
| CSRF | 所有 POST 表單需帶 session 內的 CSRF token，不符者直接拒絕 |
| 安全標頭 | 回應加 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy` 與基本 `Content-Security-Policy`（含 `frame-ancestors 'none'）；動態頁面另加 `Cache-Control: no-store`（登出後「後退」不復現資料） |
| Session | 登入成功時重設 session（防 fixation）；cookie 設 `HttpOnly` + `SameSite=Lax`；閒置超過 `LEAVE_SESSION_IDLE_MINUTES`（預設 480 分鐘）需重新登入 |
| Session 作廢 | 管理員重設密碼或使用者自改密碼後，`users.pwd_changed_at` 更新，登入早於此時間的舊 session 一律登出（簽名 cookie 無法逐出，以時間戳記檢驗） |
| 登入限流 | 兩把鎖：`IP+帳號` 與 `僅帳號`（換 IP 也躲不掉），5 分鐘內失敗 8 次即鎖定；計數寫入 `login_attempts` 表——重啟不清零、多進程一致（正式環境量大可換 Redis，介面已隔離） |
| 附件存取 | 僅本人、該生導師、同院系審批人、管理員可下載；檔名含隨機字串防枚舉 |
| 附件內容 | 副檔名白名單之外，另依檔案頭魔術位元組（`%PDF`／PNG／JFIF／OLE2／ZIP）驗證真實格式——副檔名可以改，檔案頭改不了 |
| 密碼 | 長度 8–128 碼、須含大寫／小寫字母與數字、不可與帳號相同、不可與舊密碼相同、不可為常見弱密碼（`COMMON_PASSWORDS` 擋鎖，比對忽略大小寫）；管理端設定的密碼只在回應中呈現一次，不寫進 session cookie |
| SQL | 全部參數化查詢 |
| CSV 匯出 | 自由文字若以 `= + - @` 開頭會加 `'` 前綴，防止 Excel／Sheets 公式注入 |
| 帳號枚舉 | 帳號不存在時也跑一次固定 dummy hash 比對，拉平與「密碼錯誤」的回應時間差 |
| 後台防呆 | 管理員不可停用自己、不可停用最後一位在職管理員；新增帳號強制角色白名單、帳號格式、Email 格式與導師歸屬校驗 |
| 角色下限 | 「待我審批／全部假單」僅審批人與管理員可進入（v1.0.0 前學生可翻全系統待審假單）；儀表板彙總數字同樣依角色收斂範圍 |
| 上傳邊界 | 附件超過 8 MB 回 413 並友善導回；超長原始檔名先截斷再落盤（避免超過檔案系統檔名上限而 500） |
| 開放重定向 | 400／413 的導回目標只沿用 Host 與本站相同的 referrer，其餘一律回 dashboard（referrer 是攻擊者可控的完整 URL） |
| 寫入原子性 | 提交／審批／撤回的多表寫入包在交易裡：要麼全部生效、要麼全部不發生；審批與撤回另以 `action='pending'`／`status='pending'` 條件守衛，雙擊或併發點擊只會生效一次，第二位操作者收到明確提示 |
| 通知可靠性 | Email 通道連線帶逾時（預設 10 秒，`LEAVE_SMTP_TIMEOUT` 可調）——郵件伺服器不可達時請求不會無限期掛起；且郵件不在交易內同步寄出：交易期間只入佇列，最外層交易提交後才寄（回滾則作廢），SMTP 連線期間不會占著 SQLite 寫入鎖；撤回院系級假單時院系審批人同樣收到通知 |
| 院系完整性 | 學生與院系帳號必須填寫院系（新增與編輯兩路校驗）——審批範圍依院系匹配，空院系的學生會掉進「沒人審得了」的死角 |

> `SECRET_KEY` 預設為開發用值，部署前請設環境變數 `LEAVE_SECRET`；
> 走 HTTPS 時再加 `LEAVE_COOKIE_SECURE=1`。

## 功能清單

| 角色 | 功能 |
|---|---|
| 學生 | 提交假單（含附件、**依課表預覽受影響課程**）、我的假單（按狀態篩選＋分頁）、撤回、查看審批進度與操作日誌、修改密碼 |
| 導師 | 待我審批（分頁）、全部假單（分頁＋狀態篩選）、核准/駁回、班級請假統計、CSV 匯出（串流，記憶體不隨資料量成長）、修改密碼 |
| 院系 | 同上（第 2 級複核，範圍為所屬院系） |
| 管理員 | 帳號管理（分頁＋角色篩選）、停用/編輯、重設密碼、假別管理（是否需證明、是否需院系）、稽核日誌（動作篩選＋分頁） |
共通：站內通知（分頁＋未讀篩選＋單則標為已讀；可選 Email 通道，需設定 `LEAVE_SMTP_*`）、操作日誌（誰在何時做了什麼）、淺色/深色主題切換。
維運：`GET /healthz` 健康檢查（無需登入，回傳 JSON，資料庫異常時回 503）。

```
  static/css/         樣式

```

## 環境變數

| 變數 | 預設 | 說明 |
|---|---|
| `LEAVE_SECRET` | `dev-only-change-me-in-production` | Flask `SECRET_KEY`，**部署前務必覆寫** |
| `LEAVE_COOKIE_SECURE` | `0` | 設 `1` 時 session cookie 加上 `Secure`（僅 HTTPS） |
| `LEAVE_SESSION_IDLE_MINUTES` | `480` | 閒置多久（分鐘）需重新登入 |
| `LEAVE_DB` | `leave_system.db` | 資料庫路徑（測試隔離用） |
| `LEAVE_UPLOAD_DIR` | `uploads/` | 附件上傳目錄 |
| `LEAVE_SMTP_HOST` / `LEAVE_SMTP_USER` / `LEAVE_SMTP_FROM` / `LEAVE_SMTP_PASS` / `LEAVE_SMTP_PORT` / `LEAVE_SMTP_TLS` | （未設則不啟用） | 選用 Email 通知通道；`HOST`/`USER`/`FROM` 三者齊全才啟用，發送失敗不影響主流程 |
| `LEAVE_SMTP_TIMEOUT` | `10` | SMTP 連線逾時（秒）。防止郵件伺服器不可達時請求無限期掛起 |
| `LEAVE_DEBUG` | `0` | 設 `1` 開啟 Flask debug（自動重載＋除錯器）；`start.bat` 已預設開啟，正式部署請保持 `0` |
