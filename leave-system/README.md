# 線上請假系統（原型 v1.9.0）

學生線上提交假單 → 導師審批 → （必要時）院系複核 → 核准生效。Flask + SQLite，開箱即跑。

## 啟動

```bash
# 或雙擊 start.bat
"C:\\Users\\Johnny\\.workbuddy-ai\\binaries\\python\\envs\\default\\Scripts\\python.exe" app.py
```

打開 <http://127.0.0.1:5055>。首次啟動自動建庫並寫入示範資料。

## 審批規則

- 請假 **≤ 3 天**：導師核准即生效。
- 請假 **> 3 天**，或假別標記「需院系審批」（公假、喪假）：導師核准後自動轉院系複核。
- 病假**必須**上傳證明文件。
- 駁回必須填寫理由，理由會通知學生。
- 天數按半天粒度計：同日 AM→PM = 1 天，同日 AM→AM = 0.5 天。
- **批次審批（v1.6.0）**：待審清單可勾選多張一次核准／駁回，整批包在單一交易內
  （要嘛全成、要嘛全退）；每張都重新驗權，越權、已結案或已被他人處理的單只被略過，
  單次上限 50 張。

## 表單校驗

- 單張假單最多 **90 天**。
- 最多可回溯補請 **30 天**內的假。
- **同一區間不可重複請假**；被阻擋時會提示衝突的假單編號。已駁回／已撤回的假單不佔用區間。
- 同一天請假時，**結束時段不可早於開始時段**（同日「下午→上午」是矛盾輸入：天數算 0.5、受影響課程卻按全天計）。
- 自由文字長度上限：事由 **500 字**、審批意見 **300 字**、聯絡電話 **30 字**（前端 `maxlength` 先擋，後端再校驗）。
- 聯絡電話格式：僅能包含數字與 `+ ( ) -` 空格（非必填；填了就必須像支電話）。
- 附件上限 **8 MB**，超出時頁面提示「上傳內容過大」並導回（不會出現白底錯誤頁）。

## 課表 × 請假（受影響課程）

- 學生在「提交假單」頁選定**起訖日期**與**上午／下午時段**後，系統即時算出並顯示請假期間會錯過的課程（日期、星期、時段、課程代碼）。
- 按半天粒度：同日 AM→PM 為全天；單一時段只列該上午／下午的課；多日假的中間日為全天。
- 假單送出時，受影響課程一併寫入 `leave_requests.affected_courses`（JSON），假單詳情頁可見，方便導師判斷課程衝突。
- 資料來源為 `timetable` 表，**逐生存放**；`seed` 寫入的那份一律標 `source='demo'`，
  頁面會明白標示「這是示範資料」。正式環境請匯入真實課表或對接 SIS / LMS。

## 課表檔（v1.7.0 · 逐生課表）

一列一節課，CSV。`#` 開頭為註解，表頭可省略（省略時按下列順序解讀）：

```
# 學號,星期,開始時間,結束時間,課程代碼,類型,教室,備註
2024001,mon,09:00,10:20,AIAA 2205-L01,Lecture,"Rm 102, A棟",W4
2024002,mon,13:00,14:20,DSAA 2010-L02,Lab,Rm 205
```

- **欄名很寬鬆**：中英文、簡繁與常見別名都收（`student_no`／`學號`／`学号`、`weekday`／`星期`、
  `start_time`／`開始時間`、`course`／`課程代碼`…），教務處匯出的檔可以直接貼。
- **星期**：`mon`…`fri`、英文全名、`週一`／`周一`／`星期一`、`1`…`5`。週末列會被擋下並列為錯誤。
- **時間**：`9:00` 與 `09:00` 都收，一律以**零填充的 `HH:MM`** 存庫（`'9:00' < '12:00'` 是
  `False`，不補零會把上午的課判成下午的課）。
- **模式**：`replace`（預設）對「檔案中出現的學生」先清空再寫入，對應教務處整份匯出；
  `merge` 只新增／更新，適合增量補課。同一份檔重複匯入不會長出重複的課（冪等）。
- **查無學號、格式錯誤的列不中斷匯入**：錯列會連同行號回報，其餘照常寫入。
- 單次上限 5,000 節課。

三種進場方式：

| 方式 | 說明 |
|---|---|
| 管理後台 | `/admin/timetable`：覆蓋率警示 → 選學生 → 週課表 → 單筆增刪，或貼上／上傳 CSV |
| CLI | `flask import-timetable data/timetable-sample.csv`（加 `--merge` 走增量模式） |
| 檢視 | `/timetable`：學生看自己的；導師／院系／管理員可選學生查看 |

> 覆蓋率（`timetable_coverage()`）是管理頁第一眼的數字：**多少人的課表還是示範資料**。
> 不把它降下來，整套「課表感知」都只是裝飾。

## 校曆檔（學期／假日／補課日）

系統吃一份純文字校曆檔，三種行（`#` 開頭為註解）：

```
term    2026-09-01  2026-12-25  2026-27 秋季學期
holiday 2026-10-01  2026-10-07  國慶節
makeup  2026-10-10  fri         補星期五課程（國慶假期調課）
```

- `term`：學期起訖日＋標籤；`apply_calendar()` 會把涵蓋今天的學期自動設為目前（已有目前學期則不擅改）。
- `holiday`：放假區間，**含端點自動展開成每一天**；單日只需寫一個日期、第二欄留空。假日不列受影響課程。
- `makeup`：補課／調課日，第三欄是「被補的星期幾」——可用 `mon`…`fri`、英文全名、`週五`／`周五`／`星期五`、`1`…`5`，或直接給一個日期（取那天星期幾）。補課日即使落在週六／假日也照常上課，且改按被補那天的課表計缺課。
- 單行格式錯誤不會中止匯入：錯行會列在回應的 `errors`，其餘正確照常寫入。重複匯入採冪等 UPSERT，不會長出重複資料。

三種進場方式：

| 方式 | 說明 |
|---|---|
| 管理後台 | `/admin/terms` 的「校曆檔匯入」卡片：一鍵帶入內建預設，或貼上文字 |
| CLI | `flask import-calendar [path]`；不帶路徑時自動挑選涵蓋今天的內建校曆 |
| 首次啟動 | `terms` 表為空且內建檔涵蓋今天時，`seed_calendar()` 直接匯入真實校曆，否則回退佔位學期 |

內建檔放在 `data/`，目前收錄 `hkustgz-2026-27.txt`（港科大（廣州）2026–27 學年，四學期制）。檔頭記錄來源 URL 與原文「2027 假期為 TBC」警告——政府約 2026-11 公告後，改檔重跑 `flask import-calendar` 即可更新。`PRESETS` 白名單擋路徑穿越，只認登錄過的檔名。

## 安全設計

| 項目 | 做法 |
|---|---|
| CSRF | 所有 POST 表單需帶 session 內的 CSRF token，不符者直接拒絕 |
| 安全標頭 | 回應加 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy` 與基本 `Content-Security-Policy`（含 `frame-ancestors 'none'）；動態頁面另加 `Cache-Control: no-store`（登出後「後退」不復現資料） |
| Session | 登入成功時重設 session（防 fixation）；cookie 設 `HttpOnly` + `SameSite=Lax`；閒置超過 `LEAVE_SESSION_IDLE_MINUTES`（預設 480 分鐘）需重新登入 |
| Session 作廢 | 管理員重設密碼或使用者自改密碼後，`users.pwd_changed_at` 更新，登入早於此時間的舊 session 一律登出（簽名 cookie 無法逐出，以時間戳記檢驗） |
| 登入限流 | 兩把鎖：`IP+帳號` 與 `僅帳號`（換 IP 也躲不掉），5 分鐘內失敗 8 次即鎖定；計數寫入 `login_attempts` 表——重啟不清零、多進程一致（正式環境量大可換 Redis，介面已隔離） |
| 附件存取 | 僅本人、該生導師、同院系審批人、管理員可下載；檔名含隨機字串防枚舉 |
| 附件內容 | 副檔名白名單之外，另依檔案頭魔術位元組（`%PDF`／PNG／JFIF／OLE2／ZIP）驗證真實格式——副檔名可以改，檔案頭改不了 |
| 密碼 | 長度 8–128 碼、須含大寫／小寫字母與數字、不可與帳號相同、不可與舊密碼相同、不可為常見弱密碼（`COMMON_PASSWORDS` 擋鎖，比對忽略大小寫）；管理端設定的密碼只在回應中呈現一次，不寫進 session cookie |
| SQL | 全部參數化查詢 |
| CSV 匯出 | 自由文字若以 `= + - @` 開頭會加 `'` 前綴，防止 Excel／Sheets 公式注入 |
| 帳號枚舉 | 帳號不存在時也跑一次固定 dummy hash 比對，拉平與「密碼錯誤」的回應時間差 |
| 個資讀取稽核 | 三條跨範圍 PII 讀取路徑——統計頁（`/stats`）、CSV 匯出（`/export`）、帳號清單（`/admin/users`）——每次存取皆寫入 `view_pii`／`export` 稽核軌跡，誰看過／匯出過全範圍個資皆可追溯（v1.9.0，對應 GAP-ANALYSIS D3） |
| 後台防呆 | 管理員不可停用自己、不可停用最後一位在職管理員；新增帳號強制角色白名單、帳號格式、Email 格式與導師歸屬校驗 |
| 角色下限 | 「待我審批／全部假單」僅審批人與管理員可進入（v1.0.0 前學生可翻全系統待審假單）；儀表板彙總數字同樣依角色收斂範圍 |
| 上傳邊界 | 附件超過 8 MB 回 413 並友善導回；超長原始檔名先截斷再落盤（避免超過檔案系統檔名上限而 500） |
| 開放重定向 | 400／413 的導回目標只沿用 Host 與本站相同的 referrer，其餘一律回 dashboard（referrer 是攻擊者可控的完整 URL） |
| 寫入原子性 | 提交／審批／撤回的多表寫入包在交易裡：要麼全部生效、要麼全部不發生；審批與撤回另以 `action='pending'`／`status='pending'` 條件守衛，雙擊或併發點擊只會生效一次，第二位操作者收到明確提示 |
| 通知可靠性 | Email 通道連線帶逾時（預設 10 秒，`LEAVE_SMTP_TIMEOUT` 可調）——郵件伺服器不可達時請求不會無限期掛起；且郵件不在交易內同步寄出：交易期間只入佇列，最外層交易提交後才寄（回滾則作廢），SMTP 連線期間不會佔著 SQLite 寫入鎖；撤回院系級假單時院系審批人同樣收到通知 |
| 院系完整性 | 學生與院系帳號必須填寫院系（新增與編輯兩路校驗）——審批範圍依院系匹配，空院系的學生會掉進「沒人審得了」的死角 |

> `SECRET_KEY` 預設為開發用值，部署前請設環境變數 `LEAVE_SECRET`；
> 走 HTTPS 時再加 `LEAVE_COOKIE_SECURE=1`。

## 功能清單

| 角色 | 功能 |
|---|---|
| 學生 | 提交假單（含附件、**依課表預覽受影響課程**；受本學期額度限制，超額被擋）、我的假單（按狀態篩選＋分頁）、**我的課表**、撤回、查看審批進度與操作日誌、儀表板額度用量板、修改密碼 |
| 導師 | 待我審批（分頁）、全部假單（分頁＋狀態篩選）、核准/駁回、**批次審批**、**查看轄下學生課表**、班級請假統計、CSV 匯出（串流，記憶體不隨資料量成長）、修改密碼 |
| 代理人 | 被委託期間與原審批人同一視角：看得到、審得動、附件打得開、通知同步收（過期自動失效） |
| 院系 | 同導師（第 2 級複核，範圍為所屬院系）；亦受院系層級委託；**可查本院系學生課表** |
| 管理員 | 帳號管理（分頁＋角色篩選）、停用/編輯、重設密碼、假別管理（是否需證明、是否需院系）、稽核日誌（動作篩選＋分頁）、委託審批管理（新增/刪除）、改派導師、學期管理（目前學期互斥）、每學期每假別額度設定、校曆假日（單日新增＋批次匯入）、**校曆檔匯入（學期／假日區間／補課日，內建預設一鍵帶入）**、**補課日管理（移除）**、**課表管理（覆蓋率警示／逐生週課表／單筆增刪／CSV 匯入）**、手動觸發催辦 |
共通：站內通知（分頁＋未讀篩選＋單則標為已讀；可選 Email 通道，需設定 `LEAVE_SMTP_*`）、操作日誌（誰在何時做了什麼）、PII 讀取稽核（統計頁／CSV 匯出／帳號清單每次存取皆留 view_pii／export 軌跡）、淺色/深色主題切換。
維運：`GET /healthz` 健康檢查（無需登入，回傳 JSON，資料庫異常時回 503）；`/admin/cron/escalate` 催辦升級（可設 `LEAVE_CRON_TOKEN` 給外部 cron，`LEAVE_ESCALATE_DAYS` 調門檻，同一單 24 小時只催一次）；`flask import-calendar [path]` 匯入／更新校曆、`flask import-timetable <csv> [--merge]` 匯入／更新課表（皆為冪等，政府公告假期或課表異動後重跑即可）。

| `LEAVE_DEBUG` | `0` | 設 `1` 開啟 Flask debug（自動重載＋除錯器）；`start.bat` 已預設開啟，正式部署請保持 `0` |
| `SSO_CLIENT_ID` | （未設則不啟用） | OIDC client_id；與下方四個 `SSO_*` 端點齊全時 SSO 才啟用 |
| `SSO_CLIENT_SECRET` | （未設則不啟用） | OIDC client_secret（授權碼兌換 access_token 用） |
| `SSO_AUTHORIZE_URL` | （未設則不啟用） | IdP 授權端點（跳轉登入） |
| `SSO_TOKEN_URL` | （未設則不啟用） | IdP 換 token 端點 |
| `SSO_USERINFO_URL` | （未設則不啟用） | IdP userinfo 端點（取身分聲明） |
| `SSO_REDIRECT_URI` | （未設則不啟用） | 回呼網址，須與 IdP 登記一致（本系統為 `/callback`） |
| `SSO_SCOPES` | `openid email profile` | 請求的 scope |
| `SSO_USERNAME_CLAIM` | `email` | 用來識別帳號的 claim（學號／教工號通常為 `preferred_username` 或 `sub`） |
| `SSO_ROLE_CLAIM` | （空） | 群組／角色聲明；有值且開啟自動開通時用來決定新帳號角色 |
| `SSO_DEFAULT_ROLE` | `student` | 自動開通時的預設角色（claim 角色不在白名單內時回落到此） |
| `SSO_PROVISION` | `0` | 設 `1` 時對「對應不到的 IdP 使用者」自動開通新帳號（密碼為隨機強雜湊，只能走 SSO） |
| `SSO_AUTO_LINK_EMAIL` | `1` | 設 `1` 時用 email 自動連結既有本地帳號；設 `0` 關閉此行為 |

## 單一登入（SSO / OIDC，v1.8.0）

標準 OIDC 授權碼流程已接好，但**預設關閉**——四個必要 `SSO_*` 端點／參數（`SSO_CLIENT_ID`、
`SSO_AUTHORIZE_URL`、`SSO_TOKEN_URL`、`SSO_USERINFO_URL`）齊全才啟用。啟用後：

- 登入頁出現「使用學校帳號登入」按鈕，點擊跳轉 `/login/sso` → IdP；
- IdP 回呼 `/callback`：先校驗 `state`（防 CSRF／授權碼注入），再兌換 code → 取 userinfo →
  對映到本地使用者 → 建立 session。任一環節失敗一律退回本地登入並閃錯，**不暴露錯誤細節**。
- 身分對映優先序（`sso.resolve_user`）：① `external_id` → ② username claim →
  ③ email 自動連結（可關） → ④ 自動開通（僅 `SSO_PROVISION=1`，新帳號給隨機強雜湊，
  **只能走 SSO**）。
- **本地帳密登入永遠保留為災難備援**：SSO 掛掉時管理員仍能以帳密進系統。

> ⚠️ 本版交付的是**接線通道**，不是「已完成 SSO 對接」：真實 IdP 連線參數與
> 群組／角色聲明 → 本地角色的對映規則屬各校部署設定，本倉不內含任何一家學校的憑證或假設。
> 生產環境還應補：ID-token 簽章驗證、nonce 重放防護。
